# Agora workspace

Mode: Operate. Scope: existing Faustus and Hub interfaces, their common navigation, Agora selection and room controls. Keep existing tokens, fonts, native controls and all specialised functions. No replacement brand or generated imagery.

## Direction contract

THESIS: one Agora entry serves multiple project spaces; conversations, deliberations and tasks are working modes of the selected Agora.

OWN-WORLD: Faustus Studio surfaces, typography and warm colour tokens; preserve the existing dark amber Hub conversation interface and provider controls where embedded.

STORY: choose an Agora, find or create a room, continue work with its participants and canonical history, then inspect tasks and decisions.

FIRST VIEWPORT: desktop keeps rooms beside the active work; mobile uses a compact room browser so the active work appears immediately. Agora and mode controls stay visible above it.

FORM: extension of the two incumbent Operate surfaces; no new visual world, comp or catalog tournament. Signature interaction: switching Agora or mode preserves separate drafts and room identities. Existing restrained control motion.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Product truth

The user explicitly chose Agoras as the common name. Council disappears from product navigation; deliberation retains its comparison, objections, review, synthesis and control functions. Existing Council/Group API contracts and old bookmarks remain compatible. Original room names are user data and are not rewritten.

The private browser evidence uses the actual native routers, turn drivers, shared Hub repositories and scripted model responses. Shell APIs and sessions are private fixtures. This is interface and integration evidence, not a real global-model quality evaluation or evidence of production activation.
