# Production dossiers

Each order has a production dossier. The request, deliverables and details to keep come from the order. **Orders → New order** also accepts an audience, constraints and starting materials. For an order based on an attached document, give it a title and add the document under starting materials. Enter one local file, folder or URL per line. Relative paths start in the order folder. The order page shows the saved material receipts and `hub_agora_job` includes the complete `dossier` from the first job onwards.

Use `hub_agora_order_create` or `hub_agora_order_update` to set `dossier: {audience, constraints, native}`. Supply materials in `refs`: `path`, `url`, or `app` and `object` with optional `place`, `note`, `source_rev` and `sha256`. At registration the Hub records a file's SHA-256. A folder's digest is the SHA-256 of the sorted list of relative POSIX paths and file digests, encoded as compact UTF-8 JSON. Directory traversal skips symbolic links and junctions. URLs and app objects can carry a digest supplied by the caller. A missing path or digest is visible in the receipt. Submit `refs` again to fingerprint changed inputs. Existing receipts survive edits to the order's words, its constraints or audience. Undo restores the previous receipts and settings. Pre-existing orders have a dossier derived from their recorded request and any materials they had already named.

Orders checks app references in **Plan**. The create, update and detail responses report them in `order.app_references`, plan composition reports them next to `plan`, and `hub_agora_job` exposes them in `job.app_references`. Each entry includes its zero-based index in the saved `refs`, the source, a status, and Spanish and English labels. Checks run against the configured app each time these operations respond. They leave the saved references, plan and decisions intact, and use the running app without starting it.

In Writer, give the project, Codex entry or manuscript chapter by exact title, ID, or its `hoard://writer/{project,codex,writing}/…` reference. Use `place` for a project ID or title. Existing character references such as `ficha del personaje y capítulo 1` check that the character and numbered chapter exist in the same project. Duplicate matches are reported as `ambiguous`. Writer reports `missing` after a successful lookup that finds no matching record. Other apps can confirm an exact match through their family search. A search with no exact hit or a locator the app cannot check is `unverified`. A failed app lookup is shown as `unavailable`.

When a station already compiles context, pass its result directly as `dossier.native: {app, tool, object?, source_rev?, payload}`. For example, use Writer's `wh_production_dossier`, Drucker's `drucker_engagement_get` or Coase's `coase_backend_packet`. Pass the result object in `payload`, excluding the proxy envelope. The Hub carries that object unchanged and records its JSON digest. The native app owns context compilation and the Hub does not start it when an order is read. The requesting app or an agent calls the existing contract when the source material is ready.
